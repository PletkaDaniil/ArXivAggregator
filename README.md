# ArXivAggregator

## Описание проекта

С ростом числа публикаций на [arXiv](https://arxiv.org/) исследователям становится все труднее отслеживать ключевые работы в своей области. Стандартный поиск по ключевым словам часто неэффективен для сложных и узкоспециализированных запросов. Проект направлен на создание интеллектуальной системы, которая по запросу пользователя будет находить, анализировать и структурировать релевантные научные статьи. Система должна не просто находить статьи, а ранжировать их по смысловой близости к запросу, опираясь на такие параметры, как авторы статьи, её цитируемость и полное содержание.

## Запуск основной части проекта

Для успешного запуска и дальнейшей работы необходимо заполнить файл [.env](.env.example) вашим личным API-ключом, полученным в [OpenRouter](https://openrouter.ai/), а также токеном от вашего будущего Telegram-бота.

```
python -m venv venv
```
```
venv/scripts/activate
```
```
pip install poetry
```
```
poetry install
```
```
poetry run python app/main.py
```
## Запуск раздела сравнения и дообучения моделей (опционально)

В разделе `model_testing/` реализована идея сравнения разных моделей с [HuggingFace](https://huggingface.co/) на специальном наборе запросов [queries.json](model_testing/queries.json)  по разным тематикам (например, "Computer Science", "Medicine & Healthcare", "Physics" и т.д.). Далее можно запустить дообучение модели и посмотреть, как изменится качество старой и новой (дообученной) модели.

```
poetry run python model_testing/learning.py
```

Результаты запросов сравнивались с рекомендациями, которые выдаёт ресурс [OpenAlex](https://openalex.org/); он выступал в роли тестировщика качества отбора в данном случае.


## Запуск "тестирования" (опционально)

В разделе `tests/datasets/` были размещены примеры двух датасетов: один [ground_truth.json](tests/datasets/ground_truth.json) составленный мной для оценки качества нашей системы; второй - реальные результаты, полученные при запуске, объединённые в один файл [real_results.json](tests/datasets/real_results.json)

```
poetry run python tests/evaluate_recall.py
```

## Детали реализация

1. Все взаимодействие пользователя происходит через Telegram-бота (как показано на видео) 

2. **Ход работы проекта:**

    a) Собираем релевантные статьи с arXiv за 2025 год по запросу пользователя (также ограничиваем число статей до 1200 на один запрос)

    b) Фильтруем найденные статьи и отбираем топ-150 (это осуществляется за счёт построения эмбеддингов с помощью выбранной или дообученной нами модели).
    
    с) Далее работаем с готовой выборкой из 150 статей. Собираем необходимую информацию, например, **title**, **summary** (**abstract**), **link** и другие метаданные (например, информацию об авторах и числе цитирований). Всю эту информацию получаем, используя ресурс [Semantic Scholar](https://www.semanticscholar.org/)

    d) Строим и расширяем граф связей авторов на основе новых статей. После этого пересчитываем PageRank и выдаём дополнительный численный критерий для каждого автора.

    f) Также оцениваем полное содержание каждой статьи из топ-150 и получаем ещё один численный критерий, используя модели с [OpenRouter](https://openrouter.ai/) (в нашем случае это была модель `"openai/gpt-4o-mini"`)
    
    g) На основе всех численных критериев вычисляем взвешенную сумму и формируем для пользователя ТОП-15 наиболее релевантных (качественных) статей.

3. Численные критерии:

    * Для авторов:

        * Индекс Хирша

        * Численный показатель, посчитанный по графу связей

        * Общее число работ

        * Общее число цитирований

    * Число цитирований статьи

    * Показатель качества общего содержания статьи и соответствие запросу
